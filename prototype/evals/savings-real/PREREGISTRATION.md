# Public-document research savings experiment

Status update, 2026-11-22: a real five-task pilot was subsequently supplied. The original registration and pre-pilot cost-control amendment below are retained as historical records. The dated formatting amendment at the end supersedes only answer normalization, the missing-JSON fallback and decision parsing. No confirmatory run has occurred.

Registered before any paid run, 2026-11-22. Only fake-provider tests have been authorized. No observed paid outcomes informed these tasks or this analysis.

Hypotheses: balanced reuse reduces research tokens overall; improvements vary by variant and decision. Related and stale questions can lose through lookup/verification overhead or mistakes. Report every losing task. This is a controlled corpus benchmark, not a representative sample of all research or proof that a particular user saved money.

Forty distinct frozen tasks: ten per variant; twenty REUSE, ten CHECK, ten REDO. All concern public Python documentation. Cross-document tasks are common; stale tasks isolate individual changed APIs. Phase A uses v1; Phase B uses the task's specified version. v2 is a selective overlay of actual Python 3.14.0 module documentation on Python 3.13.1 docs, not a claim about an executable mixed Python distribution. No private sessions or user usage logs are loaded. The manifest specifies redistributable licenses, upstream sources, versions and SHA-256 hashes per file. The task file contains gold facts and section anchors; these gold labels are never sent to the research model. Phase A answers may be incorrect and are retained unfiltered.

Phase A: one original research session per task, recorded Claude Code-format transcripts with actual provider usage per assistant call. Cache once. Import only these transcripts into a disposable Context Bridge library. Phase B: baseline research tools versus the same tools plus Context Bridge search/read and the unmodified balanced agent-guide. The neutral user prompt is identical across arms. Each arm has 12 calls, 2048 output tokens per call, three repetitions. Job order is shuffled with seed 65537. Default model claude-sonnet-5-5 is configurable; record requested and resolved model per call. Use thinking between_tools, low effort, no temperature, top_p or forced tool_choice. Retain full assistant content, including thinking/signature blocks, verbatim. Explicitly stop and count refusal/max_tokens. The call cap is a model-call cap, not a limit on parallel tool calls within one response.

Primary metric: for each task divide median reuse total tokens across three repetitions by median baseline total tokens across three repetitions. Total tokens = input + cache-read input + cache-creation input + output. Summarize the arithmetic mean of these paired per-task ratios. Report 100*(1-mean ratio), which may be negative. Bootstrap tasks with replacement 10000 times using random.Random(104729); percentile 2.5% and 97.5% intervals. Tasks are treated as fixed, independent experimental units; topical overlap and the single shared Phase A history can induce dependence, so intervals should not be generalized to other corpora or user populations. Report overall, each variant, each expected decision, and individual task pairs. Do not report only an overall average.

Accuracy: deterministic exact comparison of canonical structured facts; all 1–3 reference facts must match. This measures required facts, not all prose quality; independent spot checks should catch contradictions or incomplete explanations outside the fact object. Refusal, truncation, nonfinal answers, malformed fact objects and missing facts count incorrect. Accuracy per task is the mean of its three binary outcomes; compare paired task differences. Non-inferiority requires the lower endpoint of the paired bootstrap accuracy difference interval to be at least -0.05. Stale safety additionally requires observed reuse accuracy to be at least baseline accuracy on stale tasks. Claim eligibility additionally requires a complete full run and the upper token-ratio interval below 1. Phrase a successful result as meeting the registered 5-percentage-point non-inferiority rule, not literal proof of zero accuracy loss. Pilot/fake results can never support the claim.

Exclusions: none based on observed cost, accuracy, policy decision, refusal, truncation, or Phase A quality. A missing arm/repetition or zero-token baseline makes a task incomplete; keep its ID and block the confirmatory claim for the entire run. Provider transport failures leave an unresolved reserved call (possibly billed); never retry automatically. Completed responses replay from the journal and are never billed again. Hard total call cap includes original, comparison and optional grader reservations. Interrupted runs produce a partial report; pending calls require inspection before continuing. No replacement tasks or post-hoc cap/model changes in a resumed run.

Decision accuracy: fraction of reuse answers whose single explicit REUSE/CHECK/REDO line matches the frozen expected decision; missing/ambiguous lines count wrong. Report refusal, truncation, cap counts by arm. Primary analysis excludes Phase A and optional grading tokens, but their costs are reported separately. Dollars use user-supplied input/output prices per million tokens, with uncached input, cache reads and cache writes priced separately. Failed/unresolved provider calls can have unknown billable usage; these are never silently counted as free.

Secondary grading is optional (--grader-model defaults to claude-opus-5-5 when supplied without a value). Fixed rubric: all reference facts correct and no contradictory claim; ignore style, citations and reuse decisions. Input contains only reference and candidate with decision lines removed, never arm labels or usage. It is a secondary diagnostic and never replaces the primary checks. Duplicate identical grading requests are cached and costed once. Separate user-supplied grader input/output prices are required for paid grading. Export 10 seeded random answers per arm for human review (seed 271828), with empty correctness/notes columns. Selection is at answer level, not a guarantee of ten distinct tasks.

Exact analysis: prototype/savings_real_analysis.py. Run with the frozen task definitions and all Phase B records, repetitions=3; analyze() and export() produce summary.json, spot-check.csv and savings-real.md. raw-calls.jsonl preserves every reserved request and completed raw provider response. results.jsonl contains session-level outcomes. Resume configuration freezes task, analysis, runner and corpus manifest hashes, model, prices and caps. No paid run has occurred.

## Cost-control amendment (before any paid run)

Every Messages request, including grading, enables top-level automatic ephemeral caching. The task corpus and grading criteria are unchanged. Prices are supplied separately for uncached input, cache reads, cache writes and output, including separate grader rates. No cache hits are assumed in budget admission.

Paid mode requires --max-usd. Each sequential request reserves the maximum input rate across input/read/write times a text-input upper bound, plus max_tokens times output price. The text-input bound uses escaped serialized request bytes (not characters/4), 16384 framing tokens and 256 tokens for each message/content block/tool schema. Only inline text, thinking and local tool content are allowed. A computed bound above 1000000 stops the run before sending. This enforced ceiling also defines the upfront full-run worst case. The bound is deliberately conservative and may stop a run with money remaining. Recorded usage is reconciled after every response, including refusals/truncation and grader calls. Decimal arithmetic is used for admission. Unknown billable usage blocks new calls. An unexpected reservation overrun blocks further calls and marks the run incomplete; this local guard at supplied prices is not a provider invoice guarantee or account-wide spending limit.

Pilots report mean uncached/output/cache-read/cache-write tokens per call and per session, phase/arm session means, and a full-run projection for 40 original, 120 baseline and 120 reuse sessions. Grader extrapolation allows 240 judgments without assuming deduplication. Show that measured estimate alongside the enforced-ceiling worst case; neither extrapolation nor a predicted cache hit admits a call. The pilot projection is descriptive, not a confidence interval. Record mean actual characters read per session; read_doc retains its 12000-character maximum. Cache-inclusive token ratios remain the primary metric; cache pricing affects dollars, not token accounting. Corpus stays in repository/sdist, outside the wheel; --corpus-dir selects that unchanged data explicitly when installed from a wheel.

## 2026-11-22 formatting amendment (after pilot, before confirmatory run)

Reason: **pilot found formatting-only false negatives**. The real five-task claude-sonnet-5-5 pilot cost approximately $0.29 and was observed before this amendment. These are post-pilot measurement fixes, not a prospectively untouched pilot analysis. Re-grade only the saved responses; do not request new model outputs or a new model grader judgment. The original saved artifacts and labels remain unchanged; sidecars show each session's original and amended correctness, decision, compliance, tokens and calls.

There is no change to the forty tasks, questions, variants, labels, stakes, corpus, arms, neutral prompt, balanced agent guide, model settings, call caps, repetitions, bootstrap procedure, primary paired token-ratio metric, accuracy metric, non-inferiority margin or stale safety rule. Only the deterministic measurement parsing below changes. Pilot results remain exploratory and cannot qualify for a confirmatory claim.

Fact values: strip surrounding matching quotes/backticks and whitespace; compare identifiers case-insensitively. A module-qualified identifier may match a bare reference only if the entire suffix after its final dot matches exactly. Qualified references are not reduced; numbers and other values retain exact matching. JSON booleans match the string references true/false. No fuzzy matching, semantic aliases or changed reference facts are allowed: urlparse does not match urlsplit. The original grader already handled JSON booleans through case-folded strings; the explicit boolean regression test preserves that behavior.

When a valid facts JSON object exists, all required keys and values must match; prose cannot repair a wrong or incomplete facts object. If no valid facts object exists, extract each exact required value from the final answer text with the same normalization, whole-value boundaries and a limited explicit-negation veto. Explicit field/value assignments cannot be rescued by the value appearing under another field; unlabeled mixed boolean literals are treated as ambiguous. Punctuation-only values must be quoted/code-delimited, not incidental punctuation. This fallback is a surface check, not semantic judging; contradictions or values mentioned incidentally still require human spot checking. A missing value fails. Refusal, truncation and nonfinal output remain incorrect. Report the number/share using fallback (including failed fallback checks), overall and by phase/arm; the denominator is final answers actually graded by JSON or fallback. Historical rows lacking method metadata are reported as such, not inferred to be structured.

Decision parsing: one unambiguous Reuse decision: REUSE|CHECK|REDO marker anywhere in the final answer, case-insensitive, followed by an em dash, hyphen, colon or end of line. Retain acceptance of the existing en dash. Repeated markers remain ambiguous. A period followed by prose is not among the specified separators and remains non-compliant. Only final-answer text supplies the decision. Report compliance separately from decision accuracy and answer correctness; a well-formed but incorrect policy decision is compliant yet wrong. The balanced guide text and secondary model-grader rubric are unchanged.

The supplied saved pilot has facts JSON in all fifteen final sessions, so its observed text-fallback share is zero. Regression fixtures include the real module-qualified/boolean answers and clearly labelled prose-only renderings/excerpts; these do not imply a missing-JSON final occurred in this saved pilot. The colon example becomes parseable; two period-form markers remain unsupported. This limitation must stay visible in the before/after report.

Regrading is implemented by prototype/savings_real_regrade.py. It checks the saved task/corpus hashes and cross-checks final answer text, usage and call counts against raw recorded responses. It reads no library and never constructs a provider. It emits new sidecars only. Original answers, tokens, prices and source labels are retained unchanged. The registered analysis formulas are unchanged; the analysis file hash changes solely to add fallback and compliance diagnostics to reports.

## 2026-11-22 outcome-blind infrastructure amendment

Registered before any resume of the interrupted full run. Reason: transport timeout after sending may have incurred an unknown charge. The user reported an interrupted run from commit 0d0bec6 after 218 reservations, approximately $1.45 recorded, with B-research-07-baseline-0-00 unresolved and $0.06843 reserved. These are user-reported infrastructure facts only; no partial answers, correctness labels, analysis or task outcomes were opened or inspected to design this amendment. No resume or paid call is performed during implementation.

Tasks, labels, variants, corpus, arms, prompt, balanced guide, model/thinking settings, grading, analysis file/formulas, thresholds, per-session request cap and global reservation cap remain unchanged. The source analysis and grader hashes remain the previously registered values. Abandoned sends and resend reservations each count toward both the existing per-session request cap and the global reservation cap, as well as the budget; neither allowance is increased. A resend that cannot fit a remaining cap is not sent and is reported under the existing cap-reached rules. The model receives the identical request on a resend; the attempt key is local journal metadata only.

Abandonment is never automatic. The offline --abandon-unresolved EXACT_KEY command requires an explicit --abandon-by identity and --abandon-reason. It refuses unknown keys, path-like keys and any reservation with a recorded response. Each abandonment records who, UTC time, why, the exact key, full original reserved amount, possible billing and its authorized retry key. An authoritative append-only-in-program ledger is written before annotating the reservation. The full reserved amount is permanently included in recorded conservative spending, even if the retry is cheaper or a late response is later recorded. Repeating the same command does not duplicate the charge or rewrite the audit event. A response-bearing call is never abandoned as a way to seek a different answer.

One resend is authorized per logical call, under the deterministic new key EXACT_KEY--attempt-1. It must use an identical Messages body. A completed retry replays from that key, including saved tool results, without another request. If that resend is also unresolved, it may be explicitly abandoned and charged, but no third send is allowed; without a recoverable response the run remains incomplete. Other unresolved calls still block all new requests. Every retry must pass the original dollar/reservation caps with all abandonment charges already included.

Transport uses a separately staged direct TLS connection: connect before sending any HTTP headers/body, then send/read. A failure confined to the explicit connect stage is definitely not sent and may automatically retry the connection once. If both connects fail, record zero billable usage and stop; resume does not reset this automatic retry allowance. Any exception during request transmission, response headers/body reading, or response decoding is possibly billed and unresolved, with no automatic retry. Error type alone is insufficient: a timeout or connection error after send is not classified as safe. Every response, including refusals/truncation, retains its normal usage. The default read timeout increases from 120 to 300 seconds; connect timeout defaults to 30. Both are configurable and frozen in infrastructure.json, with transport/journal/runner hashes, before any new request.

The original run.json remains unchanged. Explicit offline abandonment can adopt this amendment for the exact legacy runner hash from commit 0d0bec6, provided all protected experiment hashes still match. Store the original run.json hash, original runner hash, adopter, reason and time in infrastructure.json. Normal resume compares all prior frozen experiment fields unchanged and allows only that registered runner-hash migration. Later timeout/code changes or changes to prices, caps, model, tasks, grading or analysis must refuse resume. No outcome file or library is needed for offline adoption; no provider is constructed and no request is sent by that command.

Claim eligibility: an abandon/resend does not by itself disqualify a run. Every original task must complete all arms and all three repetitions, and all previously registered accuracy, stale-safety, token-ratio and completeness criteria must still pass. Every abandonment and conservative reserved charge must be disclosed in summary.json and the generated report. Unresolved or exhausted retries that leave a cell incomplete prevent a qualifying result. Do not omit tasks, replace questions, inspect outcomes to choose retries, or select between multiple received answers. The normal pre-existing non-inferiority and bootstrap rules are unchanged.

Abandoned usage tokens are unknown. Do not invent token counters or substitute reserved dollars for tokens. Keep the primary recorded-token metric unchanged, using received responses; disclose that possibly billed abandoned work has unknown token usage and that the conservative dollar total includes its entire reservation. Report received-response dollars and abandoned reserved dollars separately, as well as their combined recorded conservative total, without refunding any abandonment. This limitation must remain visible in a qualifying report.

The offline maintenance command updates the audit ledger and frozen infrastructure metadata only; the next separately requested resume incorporates them into summary.json and the report, including incomplete reports. No partial outcomes are read just to update an infrastructure summary. Tests use fake connections and synthetic runs only. Advisory call ceilings allow two physical attempts for each optional grader judgment; primary token/statistical analysis is unchanged.
