# Public-document research savings experiment

Registered before any paid run, 2026-11-22. Only fake-provider tests have been authorized. No observed paid outcomes informed these tasks or this analysis.

Hypotheses: balanced reuse reduces research tokens overall; improvements vary by variant and decision. Related and stale questions can lose through lookup/verification overhead or mistakes. Report every losing task. This is a controlled corpus benchmark, not a representative sample of all research or proof that a particular user saved money.

Forty distinct frozen tasks: ten per variant; twenty REUSE, ten CHECK, ten REDO. All concern public Python documentation. Cross-document tasks are common; stale tasks isolate individual changed APIs. Phase A uses v1; Phase B uses the task's specified version. v2 is a selective overlay of actual Python 3.14.0 module documentation on Python 3.13.1 docs, not a claim about an executable mixed Python distribution. No private sessions or user usage logs are loaded. The manifest specifies redistributable licenses, upstream sources, versions and SHA-256 hashes per file. The task file contains gold facts and section anchors; these gold labels are never sent to the research model. Phase A answers may be incorrect and are retained unfiltered.

Phase A: one original research session per task, recorded Claude Code-format transcripts with actual provider usage per assistant call. Cache once. Import only these transcripts into a disposable Context Bridge library. Phase B: baseline research tools versus the same tools plus Context Bridge search/read and the unmodified balanced agent-guide. The neutral user prompt is identical across arms. Each arm has 12 calls, 2048 output tokens per call, three repetitions. Job order is shuffled with seed 65537. Default model claude-sonnet-5-5 is configurable; record requested and resolved model per call. Use thinking between_tools, low effort, no temperature, top_p or forced tool_choice. Retain full assistant content, including thinking/signature blocks, verbatim. Explicitly stop and count refusal/max_tokens. The call cap is a model-call cap, not a limit on parallel tool calls within one response.

Primary metric: for each task divide median reuse total tokens across three repetitions by median baseline total tokens across three repetitions. Total tokens = input + cache-read input + cache-creation input + output. Summarize the arithmetic mean of these paired per-task ratios. Report 100*(1-mean ratio), which may be negative. Bootstrap tasks with replacement 10000 times using random.Random(104729); percentile 2.5% and 97.5% intervals. Tasks are treated as fixed, independent experimental units; topical overlap and the single shared Phase A history can induce dependence, so intervals should not be generalized to other corpora or user populations. Report overall, each variant, each expected decision, and individual task pairs. Do not report only an overall average.

Accuracy: deterministic exact comparison of canonical structured facts; all 1–3 reference facts must match. This measures required facts, not all prose quality; independent spot checks should catch contradictions or incomplete explanations outside the fact object. Refusal, truncation, nonfinal answers, malformed fact objects and missing facts count incorrect. Accuracy per task is the mean of its three binary outcomes; compare paired task differences. Non-inferiority requires the lower endpoint of the paired bootstrap accuracy difference interval to be at least -0.05. Stale safety additionally requires observed reuse accuracy to be at least baseline accuracy on stale tasks. Claim eligibility additionally requires a complete full run and the upper token-ratio interval below 1. Phrase a successful result as meeting the registered 5-percentage-point non-inferiority rule, not literal proof of zero accuracy loss. Pilot/fake results can never support the claim.

Exclusions: none based on observed cost, accuracy, policy decision, refusal, truncation, or Phase A quality. A missing arm/repetition or zero-token baseline makes a task incomplete; keep its ID and block the confirmatory claim for the entire run. Provider transport failures leave an unresolved reserved call (possibly billed); never retry automatically. Completed responses replay from the journal and are never billed again. Hard total call cap includes original, comparison and optional grader reservations. Interrupted runs produce a partial report; pending calls require inspection before continuing. No replacement tasks or post-hoc cap/model changes in a resumed run.

Decision accuracy: fraction of reuse answers whose single explicit REUSE/CHECK/REDO line matches the frozen expected decision; missing/ambiguous lines count wrong. Report refusal, truncation, cap counts by arm. Primary analysis excludes Phase A and optional grading tokens, but their costs are reported separately. Dollars use user-supplied input/output prices per million tokens, with uncached input, cache reads and cache writes priced separately. Failed/unresolved provider calls can have unknown billable usage; these are never silently counted as free.

Secondary grading is optional (--grader-model defaults to claude-opus-5-5 when supplied without a value). Fixed rubric: all reference facts correct and no contradictory claim; ignore style, citations and reuse decisions. Input contains only reference and candidate with decision lines removed, never arm labels or usage. It is a secondary diagnostic and never replaces the primary checks. Duplicate identical grading requests are cached and costed once. Separate user-supplied grader input/output prices are required for paid grading. Export 10 seeded random answers per arm for human review (seed 271828), with empty correctness/notes columns. Selection is at answer level, not a guarantee of ten distinct tasks.

Exact analysis: prototype/savings_real_analysis.py. Run with the frozen task definitions and all Phase B records, repetitions=3; analyze() and export() produce summary.json, spot-check.csv and savings-real.md. raw-calls.jsonl preserves every reserved request and completed raw provider response. results.jsonl contains session-level outcomes. Resume configuration freezes task, analysis, runner and corpus manifest hashes, model, prices and caps. No paid run has occurred.

## Cost-control amendment (before any paid run)

Every Messages request, including grading, enables top-level automatic ephemeral caching. The task corpus and grading criteria are unchanged. Prices are supplied separately for uncached input, cache reads, cache writes and output, including separate grader rates. No cache hits are assumed in budget admission.

Paid mode requires --max-usd. Each sequential request reserves the maximum input rate across input/read/write times a text-input upper bound, plus max_tokens times output price. The text-input bound uses escaped serialized request bytes (not characters/4), 16384 framing tokens and 256 tokens for each message/content block/tool schema. Only inline text, thinking and local tool content are allowed. A computed bound above 1000000 stops the run before sending. This enforced ceiling also defines the upfront full-run worst case. The bound is deliberately conservative and may stop a run with money remaining. Recorded usage is reconciled after every response, including refusals/truncation and grader calls. Decimal arithmetic is used for admission. Unknown billable usage blocks new calls. An unexpected reservation overrun blocks further calls and marks the run incomplete; this local guard at supplied prices is not a provider invoice guarantee or account-wide spending limit.

Pilots report mean uncached/output/cache-read/cache-write tokens per call and per session, phase/arm session means, and a full-run projection for 40 original, 120 baseline and 120 reuse sessions. Grader extrapolation allows 240 judgments without assuming deduplication. Show that measured estimate alongside the enforced-ceiling worst case; neither extrapolation nor a predicted cache hit admits a call. The pilot projection is descriptive, not a confidence interval. Record mean actual characters read per session; read_doc retains its 12000-character maximum. Cache-inclusive token ratios remain the primary metric; cache pricing affects dollars, not token accounting. Corpus stays in repository/sdist, outside the wheel; --corpus-dir selects that unchanged data explicitly when installed from a wheel.
